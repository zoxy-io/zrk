zrk 3.0.4 fixes HTTP/3 loss recovery. zrk 3.0.3 sent probe packets every 20 ms
to a server that had not yet answered, and under load that flood was enough to
stop a proxy from completing any handshake.

```sh
brew upgrade zrk
```

## Probes follow the loss timer

The HTTP/3 loop treated every wait that timed out as the QUIC loss timer
firing. The loop also wakes for the next scheduled send, a request's
`--timeout`, the end of the run and a 20 ms idle tick, so a connection whose
peer had not replied within 20 ms sent two probe packets on every wake: about
90 Initials a second per connection, each resending whatever was
unacknowledged. RFC 9002 sends the first probe about a second in and doubles
the wait after each one. zrk now does the same.

Against a server that never answers, 3.0.3 sent 13 datagrams in the first
150 ms; 3.0.4 sends one Initial, two probes at 1 s and two at 3 s. A server that
answers within 20 ms rarely saw the difference, which is why local runs looked
fine. A 1-CPU proxy facing 1,000 new connections at once does not answer within
20 ms, and on zoxy-io/benchmark's HTTP/3 profile haproxy completed no request
in 300 s.

## Giving up a handshake

- **A handshake gets twice `--timeout`.** That is what a TCP connection gets
  between its connect and its TLS handshake. One `--timeout` also gave up
  exactly when the first probe went out.
- **A connection zrk gives up is closed with CONNECTION_CLOSE** (NO_ERROR)
  instead of going silent, so the server frees it the way it would on a TCP
  FIN. Before, a server held each abandoned attempt until its own timeout, and
  one with a fixed connection pool turned new connections away.
- **A reconnect after a failure waits 5 ms plus a random share of one
  `--timeout`,** so connections that failed together do not come back in the
  same millisecond.

## Verified

1,000 HTTP/3 connections opening at once against haproxy 3.4.8 held to a
quarter of a CPU, `--timeout 1s`, ramping from 200 to 2,000 requests/s over
20 s, on Linux: 3.0.3 completed no request and logged 18,499 connect errors.
3.0.4 completed 17,770, with 533 connect errors, all in the first 3 s.

HTTP/1.1 and HTTP/2 are unchanged.
