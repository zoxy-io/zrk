zrk 3.0.0. It adds HTTP/3 and wrk-compatible Lua scripting, and fixes
failures that only showed up against real servers. If you are coming from
2.5.0, the Homebrew release before this one, all of it is new to you. If you
ran rc.1, the scripting is new, and so are the few smaller changes listed
under "Since rc.1".

```sh
brew upgrade zrk
```

## New in 3.0

### `--http3`

zrk speaks HTTP/3 over QUIC, with the same coordinated-omission correction,
`--deadline` shedding and reports as the other transports:

```sh
zrk --http3 -c 10 -R 2000 -d 30s https://example.com/
```

Certificates are verified as they are for HTTP/1.1 and HTTP/2, so `-k` is an
opt-out here too. Reads are batched with Linux receive offload, which was worth
about 40% on 4 KiB responses. `--streams` works as it does for `--http2`.

It is labelled **experimental**, for the reasons under Known issues: on large
responses over a real network, part of what it measures is zrk.

### `--script`: wrk's Lua scripts

```sh
zrk -c 50 -R 2000 -d 30s --script users.lua http://127.0.0.1:8080/ /user/
```

`--script FILE` runs a [wrk](https://github.com/wg/wrk) script, so scripts
written for wrk and wrk2 carry over. The interpreter is LuaJIT, as in wrk, built
into the binary: there is nothing to install.

- **wrk's API.** The `wrk` table and `wrk.format`, and the hooks
  `setup(thread)`, `init(args)`, `request()`, `response(status, headers, body)`
  and `done(summary, latency, requests)`. Arguments after the URL reach `init`,
  and `--` passes ones that start with a dash.
- **One Lua state per `-t` thread**, shared by that thread's connections, as in
  wrk. A counter in a script counts per thread, as it does under wrk.
- **Every transport.** zrk reads the text `request()` returns back into a
  method, path, headers and body, so scripts work over `--http2` and `--http3`
  too.
- **A script that only edits `wrk.method`, `wrk.path`, `wrk.headers` or
  `wrk.body` costs nothing per request.** Its request becomes the fixed one,
  exactly as if `-m`, `-H` and `-b` had described it.
- **The script's time is not the server's.** `request()` runs before the pacing
  wait, and before the clock starts in `--closed` mode. `response()` runs after
  the latency is recorded.
- **What it cost is reported**, for a script with `request()`, `response()`
  or `setup()`; the static kind above runs no Lua per request and reports
  nothing. The JSON summary gains a `workload` object, with each hook's calls,
  p50 and p99, and the share of the client's threads it used. The text report
  prints the same as one line, for the hooks that were actually called. A share near 1 means the script, not the server, limits
  the run.

  ```
  script: request() 1602 calls, p50 8.1us p99 69.9us, response() 1597 calls, p50 3.7us p99 26.7us  ·  0.68% of client thread time
  ```

Closed loop against nginx, a script choosing a random path per request ran at
289k to 311k req/s from `-c 50` to `-c 1000`, the same as the fixed request,
using 13% of the client's threads.

What differs from wrk:

- **`delay()` is refused at startup.** `-R` paces requests, or `--closed` sends
  them back to back, so a script that sets its own delay is not run without it.
  `wrk.lookup`, `wrk.connect` and `thread:stop()` raise an error.
- **One request per `request()` call.** wrk's trick of returning several
  requests back to back to pipeline them is refused. `--streams` is zrk's way
  to keep several requests in flight.
- **`done`'s `requests` is per `--interval`.** wrk samples requests per second
  per thread every 100 ms; zrk samples the whole run once per `--interval`.
  `summary.errors` gains `deadline`.
- **A Lua error stops the run**, and zrk reports the file and line.

See README.md, "Scripting".

## Fixes everyone gets

- **HTTPS against Go servers failed every request.** Caddy, Traefik, Go's
  `net/http` and most Go ingress send a session ticket with an empty nonce,
  which RFC 8446 allows and zrk's TLS refused. Every zrk since v2.4.0 had it.
- **A server recycling connections was counted as errors, over `--http2`
  and `--http3`.** nginx closes a connection after 1,000 requests by default,
  and over those protocols it says so with a GOAWAY that names the requests it
  will still answer. zrk ignored that, and counted every request
  past it as a read error: up to 1.5% of a closed-loop run against an nginx
  doing nothing wrong. zrk now lets the accepted requests finish, and sends
  the others again on a new connection, once, timed from when they were due.
  HTTP/1.1 has no GOAWAY, and nothing changed there.
- **`--http2` request bodies respect flow control.** A body over 64 KiB used to
  overrun the server's windows, and a server that enforces them reset the
  stream.
- **Single-stream `--http2` responses over 64 MiB** were each an error. The
  default `-s 1` path counted every frame against a bound meant for frames
  that carry nothing; `-s` above 1 was not affected.

## What changes for you

- **A run in which no request completes exits 1**, and says why, instead of
  exiting 0 with a report of zeros. A response is a completed request whatever
  its status, so a server answering everything with a 503 still exits 0; gate
  on that with `--max-error-rate`.

  ```
  zrk: no request completed; connecting failed: CertificateVerificationFailed (-k skips certificate verification)
  ```

- **Closed-loop p99 goes up against servers that recycle connections.** At
  `--closed -c 4 -s 16` over HTTP/2 against nginx, p99 goes from about 1.8 ms
  to about 4.5 ms; p50 and p90 do not move. That is not a regression: the
  requests that used to be dropped as errors are now measured, reconnect
  included, and they sit right on the p99 line.
- **`-H "Host: …"` replaces the default `Host`.** Over HTTP/1.1 it used to be
  sent as a second `Host` line, which a server is told to reject with a 400.
  Over HTTP/2 and HTTP/3 it becomes the request's `:authority`.
- **An argument after the URL is an error without `--script`.** It used to
  replace the URL silently. Empty arguments are still ignored.
- **`-s file.lua` says to use `--script`.** wrk's `-s` is its script flag; in
  zrk `-s` is `--streams`.

## Since rc.1

Scripting, all of the section above, and four changes that apply without a
script:

- **`-H "Host: …"` replaces the default `Host`**, and over HTTP/2 and HTTP/3
  becomes the request's `:authority`. In rc.1 it was sent as a second `Host`
  line over HTTP/1.1.
- **An argument after the URL is an error without `--script`.** In rc.1 it
  silently replaced the URL.
- **`-s file.lua` says to use `--script`** instead of reporting a bad number.
- **The runtime is zio v0.19.1**, the event loop every connection runs on,
  from rc.1's pre-release commit of 0.17.

Every other flag, report and gate is unchanged from rc.1. Before the release, each part went
through code review, repeated after every fix until it came back clean. That
found 17 issues that tests, mutation checks and live runs had missed, all
fixed. Three of them could crash the process from a script, and one made an
oversized `--http3` request retry forever instead of failing. The changes are in
[#94](https://github.com/zoxy-io/zrk/pull/94),
[#95](https://github.com/zoxy-io/zrk/pull/95),
[#96](https://github.com/zoxy-io/zrk/pull/96) and
[#97](https://github.com/zoxy-io/zrk/pull/97).

## Known issues

- **`--http3` is slow on large responses over a real network.** Each stream's
  receive window is 16 KiB, so one stream moves at most 16 KiB per round trip.
  Against Google's and Cloudflare's home pages it completes with no errors but
  a p50 of 1.5 to 1.7 s, where `--http2` takes 100 to 130 ms. Compare against
  `--http2` before trusting an `--http3` latency for a response beyond a few
  tens of KiB across a network. [#89](https://github.com/zoxy-io/zrk/issues/89).
- **An `--http3` connection quiet for twice `--timeout` is replaced.** zrk
  sends no keepalive yet, so at a rate low enough to leave connections that
  idle, some requests carry a fresh handshake in their latency.
- **An `--http3` request has to fit one QUIC stream write**, 4 KiB with its
  headers. A larger `--body` is refused up front, and a larger scripted request
  stops the run.
- **`--deadline-abort` can cut a request off late** on a non-multiplexed
  connection, when `--deadline` is much shorter than `--timeout` and the
  offered rate is low. [#73](https://github.com/zoxy-io/zrk/issues/73).
- **A script with `response()` keeps one whole response body per request in
  flight**, with no size limit. Against very large responses, that is the
  memory it takes.
- **ECDSA test certificates made with macOS's `/usr/bin/openssl`** are refused
  by `--http3`, even with `-k`. Make them with OpenSSL 3.

## For embedders

`runner.run`, which is what `docs/library.md` documents, takes the same
arguments as in 2.5.0. Its `Report` gains a `workload` field. The other
exported modules changed in ways a direct caller has to follow:

- **`cli.Config.workload`** generates every request instead of replaying the
  fixed one: a `workload.Workload` with `open`, `next(seq)`, `close`, and the
  optional `response` and `timing`. `docs/library.md`, "Generating requests",
  has the contract. `script.Script` is `--script` built on it.
- **`cli.Config`** also gains `http3`, which selects QUIC, and `script_path`
  and `script_args`.
- **`stats.Fleet.init`** takes one more parameter, `enable_h3`, for `--http3`.
- **`http.buildRequestFields`** is new: a request's field list for HTTP/2 and
  HTTP/3, from the config and a `workload.Request`.
- **`h2conn.Session.beginStream`** no longer writes the request body; drive it
  with `reserveBody` and `writeBody` as credit arrives, or call `exchange`.
- **`h2conn.Incoming`** has new `window` and `refused` variants, and
  `h2conn.Error` a new `Refused`. An exhaustive `switch` over either needs the
  cases.
- **`h2conn.Session.observer`** sees each response's fields and DATA, for a
  caller that keeps responses.
- **`connection.Counters`** has a new field, `first_connect_error`.
- **zio is v0.19.1**, from the 0.17 commit 2.5.0 pinned. `docs/library.md` has
  you construct a `zio.Runtime` yourself, so pin the same version in your own
  `build.zig.zon`, or the build carries two.
- **`cli.ParseError`** has five new errors: `Http3WithHttp2`, `Http3WithoutTls`,
  `Http3BodyTooLarge`, `ScriptViaStreams` and `UnexpectedArgument`. An
  exhaustive `switch` over it needs the cases. `cli.parse` returns the last
  for any non-empty argument after the URL without `--script`; it used to take
  such an argument as the URL.

## Verified against

Before the tag, a release build of this code ran against real servers rather
than the ones the test suite stands in for. No run had a connect, read, write
or timeout error, and every response was a 2xx except where a script asked
Cloudflare for paths that do not exist, which it rightly answered with 404:

| Server | Transports | Also exercised |
| --- | --- | --- |
| Caddy 2.9 (Go) | HTTP/1.1 and HTTP/2, cleartext and TLS; HTTP/3 | `--streams 4` and `8`, `--closed`, 4 KB `--http3` bodies, 300 KB `--http2` bodies, scripts with every hook |
| nginx 1.27, default `keepalive_requests` | HTTP/1.1, h2c | GOAWAY at `-s 8`, `--closed` at 300k req/s, `--disable-keepalive`, a ramp, `--deadline`, a static script |
| www.google.com | HTTP/1.1, HTTP/2, HTTP/3 | a `request()` script over HTTP/2 |
| cloudflare-quic.com | HTTP/2, HTTP/3 | `setup`/`response`/`done` over both |

Against rc.1's release binary, closed loop on each transport, throughput and
latency were the same within run-to-run noise.
