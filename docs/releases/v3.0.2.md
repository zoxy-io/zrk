zrk 3.0.2 reduces the memory used by latency statistics on large connection
fleets. It keeps the existing histogram precision and latency range.

```sh
brew upgrade zrk
```

## Statistics memory follows thread count

Previously, every connection owned a live histogram and a reporting snapshot:
272 KiB of histogram counters per connection, or about 259 GiB at one million
connections.

Connections now share up to `--threads` statistics shards. Each shard owns one
136 KiB histogram, so sixteen shards require 2.125 MiB of histogram counters,
plus the fixed reporting histograms, regardless of connection count.

HTTP/1.1, HTTP/2, and HTTP/3 all use the shards. Each response's latency and
counters are updated together under a short lock, keeping live snapshots
consistent when the runtime moves coroutines between threads. Reports merge
the shards directly, removing the per-connection histogram copies.

Every latency sample is still recorded at three significant figures over
1 microsecond to 60 seconds. Values above the ceiling are still clamped.
CLI flags and report fields are unchanged.

## Measured memory reduction

A localhost HTTP/1.1 comparison on macOS/aarch64 used release builds, 1,000
connections, four threads, 2,000 requests/s, and a two-second run:

| Build | Peak resident memory |
| --- | ---: |
| Before sharding | 365.86 MiB |
| With sharding | 100.11 MiB |

That is a 72.6% reduction, with zero errors in both runs. The exported
histograms retained three significant figures and the 60-second ceiling.

Transport buffers, TLS state, and coroutine stacks still scale with connection
count. A full million-connection test has not been run.

## Embedding

The third argument to `stats.Fleet.init` is now a shard count, replacing the
publish interval. Pass `cfg.threads` for the same allocation as the CLI.
`buildParams` supplies a shared `stats_mutex` alongside each connection's
histogram and counters; use the `connection.note*` helpers for updates.
Standalone connections can still own their histogram and counters exclusively
and omit the mutex. See the [library documentation](https://github.com/zoxy-io/zrk/blob/v3.0.2/docs/library.md).
